# 밋업 → AI 오피스 이식 킷 (Port Kit)

밋업(6인 비공개 모임 앱)에서 실제로 돌아가는 **소셜 · 알림 · 에디터 · 첨부 ·
할일/회의/일정/기록/인사이트** 흐름을 다른 앱에 그대로 옮기기 위한 문서 묶음.

> 이 폴더는 **설명 + 실제 소스 복사본** 세트다.
> 문서를 읽다가 "코드 어디?" 싶으면 전부 [`reference/`](reference/) 안에 있다.
> 복사본은 밋업 저장소의 실제 경로를 그대로 미러링한다
> (`reference/src/features/social/like-comment-block.tsx`
> = 밋업의 `src/features/social/like-comment-block.tsx`).

---

## 왜 이 폴더가 또 있나

`docs/guides/ai-office/` 에 이미 긴 가이드(`social-notifications-guide.md`,
`meeting-task-flow-guide.md`)가 있다. 그건 **설명 중심**이다.
이 폴더는 그걸 대체하는 게 아니라 **실제로 이식할 때 옆에 띄워놓는 작업 킷**이다.
차이는 셋:

1. **코드 복사본이 실물로 들어있다.** 문서 안 코드블록을 다시 타이핑하지 말고
   `reference/` 파일을 그대로 복붙 → 이름만 바꾼다.
2. **"팝업 아님" 원칙이 문서 전체에 박혀 있다.** 밋업 UI가 직관적인 이유의 절반은
   *모든 것이 URL 을 가진 새 페이지*라는 점이다. 이걸 먼저 못 박고 시작한다.
3. **이식 순서가 정해져 있다.** 아래 순서를 어기면 반드시 되돌아온다.

## 한 장 요약 — 이식하는 것의 정체

```
              ┌──────────────────────────────────────────────┐
   화면       │  목록 페이지  →  상세 페이지  →  편집 페이지   │  전부 URL
              │  (팝업 없음. 모달은 "뷰어/확인" 용도만)       │
              └───────────────┬──────────────────────────────┘
                              │ 호출
              ┌───────────────▼──────────────────────────────┐
   데이터     │  src/lib/data/*.ts  (도메인별 함수)           │
   레이어     │  · 조회 함수                                  │
              │  · 변경 함수 = 저장 + recordActivity + notify │ ← 여기가 핵심
              └───────┬───────────────┬──────────────────────┘
                      │               │
        ┌─────────────▼──┐      ┌─────▼─────────────────────┐
        │ Postgres (RLS) │      │ Edge Function `notify`     │
        │ · 도메인 테이블 │      │ · 운영자 글로벌 토글 확인   │
        │ · *_likes      │      │ · 수신자 결정 (actor 제외)  │
        │ · *_comments   │      │ · 개인 prefs 필터           │
        │ · activities   │      │ · Web Push 발송            │
        │ · attachments  │      └────────────┬───────────────┘
        └────────────────┘                   │
                                    ┌────────▼────────┐
                                    │ public/sw.js    │ → 기기 알림
                                    └─────────────────┘
```

**외울 문장 하나:**
> 화면은 Supabase 를 직접 부르지 않는다. 화면은 `lib/data/*` 만 부르고,
> `lib/data/*` 가 저장 · 활동기록 · 알림 세 가지를 한 번에 책임진다.

이 규칙 하나가 깨지면 "댓글은 달리는데 알림이 안 온다 / 최근 활동에 안 뜬다"가
바로 시작된다. 밋업에서 알림·피드가 빠짐없이 도는 이유는 오직 이것 때문이다.

## 이식 범위 (사용자가 요청한 것)

- ✅ 댓글 · 좋아요 · 답글 + 알림 → 01, 02
- ✅ 멤버 활동 시 알림 / 최근 활동 노출 → 02, 03
- ✅ 자기 페이지에서 내 할일 확인 → 03, 05
- ✅ 할일 / 회의 / 일정 / 기록 / 인사이트에서 에디터 사용 → 04, 05, 06, 07
- ✅ 첨부파일 → 04
- ✅ 팝업이 아닌 새 페이지 UI → 00, 08
