# 06 · 회의 — 일정 · 참석 · 회의록 · 할일 배정

밋업에서 "회의"는 **하나가 아니라 3층**이다. 이 분리가 이식할 때 가장 자주 뭉개진다.

```
일정 (meetings)          — 언제 어디서 모이나. 미래형.
   │  meeting_id (nullable)
회의록 (meeting_notes)   — 무슨 얘기를 했나. 과거형.
   │  note_id (nullable) + meeting_id (nullable)
할일 (tasks)             — 그래서 누가 뭘 하나. 실행형.
```

**셋 다 서로 없이도 존재할 수 있다.** 4가지 조합이 전부 유효하다.

| 일정 | 회의록 | 상황 |
| --- | --- | --- |
| ✅ | ❌ | 아직 안 한 모임 / 회의록 미작성 |
| ✅ | ✅ | 정상 흐름 |
| ❌ | ✅ | 카톡·전화로 나눈 얘기를 기록 |
| ❌ | ❌ | 그냥 만든 할일 |

## 1. 일정 (`meetings`)

```ts
type Meeting = {
  id, workspace_id,
  type_id: string | null,      // 일정 종류 (정기모임/스터디/번개…) — 선택 기능
  project_id: string | null,
  title, description, location,
  starts_at: string,           // timestamptz
  ends_at: string | null,
  created_by: string,          // = 호스트
  created_at, updated_at,
};
```

생성 시 **전체 멤버에게 알림 + 활동 기록**:

```ts
await notify({
  type: "new_meeting", workspace_id, actor_id: createdBy,
  title: "📅 새 일정",
  body: `${name} 님이 「${title}」 일정을 등록했어요.`,
  url: `/meetings/${id}`, tag: `meeting-${id}`,
});
```

### datetime-local ↔ timestamptz (가장 자주 틀림)

```ts
// 폼 → DB : datetime-local 은 로컬 시각 문자열. Date 로 감싸 ISO 로.
starts_at: new Date(form.startsAt).toISOString()

// DB → 폼 : ISO 를 로컬 'YYYY-MM-DDTHH:mm' 로 되돌린다 (slice 금지!)
function toLocalInput(iso: string) {
  const d = new Date(iso);
  const pad = (n: number) => String(n).padStart(2, "0");
  return `${d.getFullYear()}-${pad(d.getMonth()+1)}-${pad(d.getDate())}T${pad(d.getHours())}:${pad(d.getMinutes())}`;
}
```

`iso.slice(0,16)` 로 하면 **UTC 기준이라 한국 시간이 9시간 밀린다.**
반면 `due_date` 같은 **날짜만** 필드는 `iso.slice(0,10)` 이 맞다 (시각이 없으니).

## 2. 참석 응답 — 밋업스러움이 가장 잘 드러나는 부분

`meeting_attendees(meeting_id, user_id, status, reason, responded_at)`,
status 는 `attending | late | absent`.

📄 UI: `reference/src/pages/meeting-detail.tsx` 의 「내 참석」 섹션

**규칙 4개**

1. **마감 = 일정 4일 전 23:59.** 이후엔 운영자/호스트만 변경 가능.
   ```ts
   const d = new Date(meeting.starts_at);
   d.setDate(d.getDate() - 4); d.setHours(23, 59, 0, 0);
   const canChangeMine = Date.now() <= d.getTime() || canManage;
   ```
2. **지각/불참은 사유를 받는다.** 참석은 원클릭.
3. **활동 피드에는 지각/불참만 기록.** 참석 토글은 노이즈가 너무 많다.
4. **알림은 운영자에게만** (`type: "attendance_reported"` → `getRecipients` 가
   owner/admin 으로 좁힘).

```ts
title: status === "late" ? "⏰ 지각 알림" : "🙏 불참 알림",
body: `${name} 님이 「${meeting.title}」 ${verb}${reason ? ` — ${reason}` : ""}`,
tag: `attendance-${meeting.id}-${userId}`,   // 사람당 1개로 덮어쓰기
```

버튼은 3분할 `inline-flex border` 안의 pill. 선택된 「참석」만
`border-accent-teal bg-accent-teal text-accent-foreground` — 액센트 3용도 중
"현재 상태" 에 해당한다.

## 3. 회의록 (`meeting_notes`)

```ts
type MeetingNote = {
  id, workspace_id,
  meeting_id: string | null,   // 없으면 단독 회의록 (카톡 등)
  title,                       // 폼에 입력칸이 없다 — 자동 생성
  agenda: string | null,       // 줄바꿈으로 구분된 텍스트. 별도 테이블 아님
  content: string | null,      // 에디터 HTML
  summary: string | null,
  created_by, created_at, updated_at,
};
```

**제목 입력칸이 없는 이유** — 연결된 일정이 있으면 그 제목을 쓰고, 없으면
`YYYY-MM-DD 회의록`. 매번 제목을 고민하게 만드는 마찰을 없앴다.

```ts
function autoTitle(meetingId, meetings) {
  if (meetingId) { const m = meetings.find(x => x.id === meetingId); if (m) return m.title; }
  return `${년}-${월}-${일} 회의록`;
}
```

**아젠다가 별도 테이블이 아닌 이유** — 순서 있는 문자열 목록일 뿐이고, 개별 아젠다에
좋아요·댓글이 붙지 않는다. 저장은 `join("\n")`, 표시는 `split("\n")` + 번호.
테이블을 하나 아끼는 게 아니라 **폼/조인/RLS 를 통째로 아낀다.**

생성 시 전체 알림: `type: "new_note"`, `📝 새 회의록`.

## 4. ★ 회의록 폼 — 저장 한 번에 할일까지

📄 `reference/src/features/notes/note-form.tsx` (659줄) — **이 문서의 핵심 파일**

```
Meeting Note
2026-08-21 회의록                       ← 자동 제목 프리뷰 (실시간)

연결
[일정 select — "— 일정 미연결 (카톡 등) —" 포함]

아젠다
1. [안건 인풋]  ×
2. [안건 인풋]  ×
+ 아젠다 추가

회의 내용
[RichEditor minHeight=240]

할일
회의 결과로 정해진 액션 아이템. 저장 시 회의록에 연결된 할일로 등록됩니다.
┌───────────────────────────────────────────────── bg-surface-muted
│ 전체 과제 · 모든 멤버에게 일괄 배정
│ [내용            ] [기한]  [멤버 6명에게 추가]
└─────────────────────────────────────────────────
[내용          ] [담당자 ▾] [기한] ×
[내용          ] [담당자 ▾] [기한] ×
[+ 할일 추가] [+ 기존 할일 불러오기]

[임시저장]                        [취소] [삭제] [저장]
```

### 폼이 부모에게 넘기는 것 (딱 2개)

```ts
onSubmit(
  { meeting_id, title, agenda, content, summary },  // 회의록 값
  actionItems: ActionItemDraft[],                    // 할일 행들
)

type ActionItemDraft = {
  id: string | null;          // 기존 할일이면 id, 새 행이면 null
  title: string;
  assignee_id: string | null;
  due_date: string;           // 'YYYY-MM-DD' 또는 ''
};
```

빈 제목 행은 제출 전에 걸러진다. 폼은 DB 를 모른다 — 저장은 페이지가 한다.

### 세 가지 배정 방식 (다 필요하다)

| 방식 | 언제 | UI |
| --- | --- | --- |
| **개별 추가** | 사람마다 다른 일 | `+ 할일 추가` → 행 하나 |
| **전체 일괄 배정** | "다음 모임까지 책 1챕터" 처럼 **같은 일을 전원에게** | 상단 회색 박스. 멤버 수만큼 행이 한 번에 생성 |
| **기존 할일 불러오기** | 이전에 만든 할일을 이 회의록에 연결 | 체크박스 다중선택 패널 |

**일괄 배정은 할일 row 를 멤버 수만큼 만든다** (1개 아님). 각자 자기 진행률과
자기 댓글을 갖기 위해서다.

```ts
const rows = members.map((m) => ({ id: null, title: t, assignee_id: m.user_id, due_date: due }));
```

「기존 할일 불러오기」 패널은 이미 이 회의록에 있는 항목을 후보에서 제외하고,
다른 회의록에 연결된 것은 `· 다른 회의록에 연결됨` 을 표시한다.

## 5. ★ `syncTasksForNote` — 저장 알고리즘

📄 `reference/src/lib/data/tasks.ts` 의 `syncTasksForNote`

**문제:** 편집 화면에서 사용자가 행을 추가·수정·삭제했다. DB 를 어떻게 맞추나?
**하면 안 되는 것:** 전부 지우고 다시 만들기 — 완료 상태·댓글·첨부가 다 날아간다.

```
현재 note 에 연결된 할일 목록을 가져온다
   ├─ 폼에 없는 것        → 삭제 (delete)
   ├─ 폼에 있고 id 있음    → 수정 (update, note_id 를 이 노트로 강제)
   └─ 폼에 있고 id 없음    → 생성 (create)
```

```ts
const existing = await getTasksForNote(noteId);
const keepIds = new Set(rows.keep.map(r => r.id));

for (const t of existing) if (!keepIds.has(t.id)) await deleteTask(t.id);   // ① 삭제
for (const k of rows.keep) await updateTask(k.id, { ...k.patch, note_id: noteId }); // ② 수정
for (const c of rows.create) await createTask({ …, note_id: noteId, meeting_id }, createdBy); // ③ 생성
```

**순서가 중요하다.** 삭제를 먼저 해야 "A 를 지우고 같은 제목 B 를 새로 만드는"
경우에 중복이 안 생긴다.

`note_id` 를 patch 에 **강제로 넣는 것**이 포인트 — 「기존 할일 불러오기」로 끌어온
할일(다른 노트나 무연결)이 실제로 이 회의록에 연결된다.

**새 회의록 작성에도 같은 함수를 쓴다** (`keep` 이 비어있을 뿐).
저장 경로를 하나로 유지하는 게 버그를 줄인다.

### 저장 한 번에 나가는 알림

김대표가 새 회의록을 저장하면서 박이사·이대표에게 할일 1개씩 배정했다면:

```
new_note  → 전체 멤버 (김대표 제외)     1건
new_task  → 박이사                      1건
new_task  → 이대표                      1건
```

`createTask` 안에서 자동으로 나간다. 회의록 페이지는 알림 코드를 한 줄도 안 쓴다.
**이것이 원칙 2(데이터 레이어가 책임진다)의 실제 이득이다.**

## 6. 역참조 — 이 데이터가 어디에 뜨나

한 곳에 저장하고 여러 화면에서 다시 읽는다.

| 화면 | 무엇 | 쿼리 |
| --- | --- | --- |
| 일정 상세 | 할일 진행률 + 회의록 목록 | `getNotesForMeeting(meetingId)` |
| 회의록 목록 | 행마다 진행률 | `getTasksForNote` 결과를 Map 으로 |
| 회의록 상세 | 액션 아이템 리스트 + 진행률 + 참석자 | `getTasksForNote(noteId)` |
| 할일 목록 | 전체 / 내 할일 | `getTasks({...})` |
| 할일 상세 | 연결된 회의록 링크 | `getNote(task.note_id)` |
| 홈 | 확인이 필요한 일 / 내 할일 | 03 문서 |
| 활동 피드 | `created_meeting_note`, `created_task`, `completed_task` | 03 문서 |

📄 회의록 상세의 할일 리스트 마크업은 `reference/src/pages/note-detail.tsx` 참고
(행 전체가 `/tasks/:id` 링크 + 사각 체크 아이콘 + 담당/기한 + `TaskProgress`).

회의록 상세 하단에 이 안내를 두면 사용자가 헤맬 일이 없다:

> 행을 클릭하면 상세에서 상태 변경 · 본문 / 첨부 편집이 가능합니다.

## 7. 안건 · 투표 (선택이지만 궁합이 좋다)

📄 `reference/src/lib/data/agendas.ts`, `reference/src/pages/agenda-detail.tsx`
