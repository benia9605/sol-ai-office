# 03 · 활동 피드 · 개인 화면 (최근 활동 / 내 할일 / 내 활동)

"멤버가 뭔가 하면 남들에게 보인다"의 **인앱** 절반. 푸시(02)가 기기 알림이라면
이건 화면 안에 남는 기록이다. 둘은 별개 시스템이고 **둘 다 있어야** 밋업처럼 된다.

| | 푸시 알림 (02) | 활동 피드 (이 문서) |
| --- | --- | --- |
| 저장 | 안 함 (휘발) | `activities` 테이블에 append-only |
| 대상 | 관계자만 | 워크스페이스 전체가 봄 |
| 목적 | 지금 알려야 하는 것 | "옆 사람이 뭐 했나" 훑기 |
| 호출 | `notify()` | `recordActivity()` |

## 1. `activities` — 테이블 하나로 전부 커버

```sql
create table public.activities (
  id            uuid primary key default gen_random_uuid(),
  workspace_id  uuid not null references public.workspaces(id) on delete cascade,
  user_id       uuid not null references auth.users(id) on delete cascade,
  action        text not null,          -- 'created_task' | 'liked_insight' | …
  resource_type text,                   -- 'task' | 'insight' | 'meeting' | 'note' | …
  resource_id   uuid,
  metadata      jsonb not null default '{}'::jsonb,
  created_at    timestamptz not null default now()
);
create index activities_workspace_idx on public.activities(workspace_id, created_at desc);
create index activities_user_idx      on public.activities(user_id, created_at desc);
```

**RLS 는 append-only** — 멤버 누구나 읽기, 본인 행만 insert, **update/delete 정책 없음**.
정책이 없으면 RLS 하에서 그 동작은 아예 불가능하다. 이게 곧 "기록은 조작 못 함"이다.

**자원별 테이블을 만들지 마라.** `resource_type` + `resource_id` 폴리모픽 한 쌍이면
새 자원이 생겨도 마이그레이션이 필요 없다.

### `metadata` 에 무엇을 넣나

FK 조인 없이 피드 한 줄을 그릴 수 있을 만큼만 **비정규화해서 복사**한다.

```ts
metadata: { title: "3분기 전략 회의" }                      // 기본
metadata: { title: "…", excerpt: content.slice(0, 80) }     // 댓글
metadata: { title: "…", reason: "출장" }                    // 지각/불참
metadata: { title: "…", choices: "찬성", poll_type: "single" } // 투표
metadata: { title: "…", reading_id: "…" }                   // 중첩 라우트용 부모 id
```

원본이 삭제돼도 피드 줄은 남는다. 이게 **의도된 동작**이다 —
"그때 이런 일이 있었다"는 사실은 지워지면 안 된다.

## 2. `recordActivity` — 실패해도 조용히 넘어간다

📄 `reference/src/lib/data/activities.ts`

```ts
export async function recordActivity(input: ActivityInput, userId: string) {
  try {
    await supabase.from("activities").insert({ ...input, user_id: userId });
  } catch {
    /* logging is best-effort */
  }
}
```

도메인 변경 함수 안에서 저장 직후 호출한다.

```ts
await recordActivity(
  { workspace_id, action: "created_task", resource_type: "task",
    resource_id: t.id, metadata: { title: t.title } },
  createdBy,
);
```

### 어떤 사건을 기록하나

| 기록한다 | 기록 안 한다 |
| --- | --- |
| 생성 (`created_*`) | 편집 (`updated_*`) — 피드가 지저분해짐 |
| 완료 (`completed_task`, `completed_reading`) | 조회 |
| 공유/발행 (`shared_insight`, `created_writing`) | 삭제 |
| 좋아요·댓글 (`liked_*`, `commented_*`) | 임시저장 |
| 투표 (`voted_agenda`), 합류 (`joined_workspace`) | 로그인 |

**완료 전환은 "이전 상태가 done 이 아니었을 때만"** 기록한다. 안 그러면 편집 저장
때마다 "완료했습니다"가 반복 기록된다.

```ts
const wasDone = prev?.status === "done";
if (!wasDone && updated.status === "done") { await recordActivity(...); await notify(...); }
```

📄 `reference/src/lib/data/tasks.ts` 의 `updateTask` 참고.

## 3. 피드 UI — 한 컴포넌트, 두 화면

📄 `reference/src/components/dashboard/activity-feed.tsx`

```tsx
<ActivityFeed activities={activities ?? []} />          // 홈: 헤더 + "전체 보기 →"
<ActivityFeed activities={activities ?? []} bare />     // /activity: 헤더 없이 전체
```

홈은 `getWorkspaceActivities(workspace.id, 5)` 로 5건, `/activity` 는 limit 없이 전부.

### 한 줄의 문장 구조

```
(아바타) 김대표 새 할일을 추가했습니다 · 「3분기 예산안」 · 「본문 앞 80자」
         3시간 전
```

문장은 **세 함수**가 만든다. 새 자원을 붙이면 **이 셋만 고치면 된다.**

```ts
verbFor(a)        // action → "새 할일을 추가했습니다 ·"
targetTextFor(a)  // metadata.title → 「…」
linkFor(a)        // resource_type + resource_id → "/tasks/abc"
```

`subtext` 는 `metadata` 에서 `reason ?? excerpt ?? choices` 순으로 하나만 고른다.

### 상대 시간 규칙

```
< 1분   → "방금 전"
< 1시간 → "N분 전"
< 1일   → "N시간 전"
< 30일  → "N일 전"
그 이상 → "8월 21일"   (Intl.DateTimeFormat ko-KR)
```

📄 `activity-feed.tsx` 하단 `relativeTime()`. 그대로 복사.

### 새 자원을 피드에 노출시키는 3줄

```ts
// verbFor
case "commented_project": return "프로젝트에 댓글을 남겼습니다 ·";
// linkFor
case "project": return `/projects/${a.resource_id}`;
// 중첩 라우트면 metadata 에서 부모 id 를 꺼낸다
case "reading_note": {
  const readingId = a.metadata?.reading_id;
  if (typeof readingId !== "string") return null;
  return `/readings/${readingId}/notes/${a.resource_id}`;
}
```

`linkFor` 가 `null` 을 반환하면 `<Link>` 없이 텍스트로만 렌더된다 —
자원이 삭제된 옛 활동에서 죽은 링크가 생기지 않는다.

## 4. 「확인이 필요한 일」 — 홈 상단 개인 패널 ★

밋업이 직관적이라는 인상의 **80%가 이 패널**이다. 홈에 들어오자마자
"내가 지금 해야 할 것"이 한 상자에 모여 있다.

📄 `reference/src/components/dashboard/my-action-panel.tsx`

```
확인이 필요한 일  4
┌──────────────────────────────────────────── border-accent-teal/40
│ 출석   3분기 전략 회의            8월 24일 (일) 까지 응답
│ 투표   회식 장소 정하기                        2일 남음
│ 할일   예산안 초안 작성                      오늘 마감
│ 할일   경쟁사 리서치                       3일 지남  ← text-danger
│ 초안   임시저장된 글이 있어요        2건 — 마저 완성해 보기
└────────────────────────────────────────────
```

**핵심 규칙 4가지**

1. **항목이 0개면 섹션 자체를 렌더하지 않는다.** `if (total === 0) return null;`
   빈 카드가 남아 있으면 "할 일 없음"이 시각적 소음이 된다.
2. **행 = `<Link>`.** 누르면 그 자원 상세 페이지로. 팝업 아님(원칙 1).
3. **왼쪽 태그 열은 고정폭**(`w-10`) + 대문자 트래킹. 오른쪽은 마감 정보.
4. **지연은 `text-danger`**, 그 외는 무채색. 여기가 danger 색을 쓰는 몇 안 되는 곳.

넣는 항목 (이식 대상 앱 도메인에 맞게 고르면 된다):

| 태그 | 조건 | 링크 |
| --- | --- | --- |
| 출석 | 다음 모임에 아직 응답 안 함 + 마감 안 지남 | `/meetings/:id` |
| 투표 | 내가 아직 투표 안 한 열린 안건 | `/agendas/:id` |
| 할일 | 내 담당 + 미완료 + (오늘 마감 또는 지남) | `/tasks/:id` |
| 초안 | 내 임시저장 글/인사이트 개수 | `/me/posts` |

마감 라벨은 `taskDueLabel()`:
`3일 지남` / `오늘 마감` / `내일 마감` / `N일 남음` / `기한 없음`.
📄 함수 원본이 `my-action-panel.tsx` 하단에 있다.

## 5. 「내 할일」 — 기한 버킷 뷰

📄 `reference/src/components/dashboard/my-tasks-preview.tsx`

목록을 그냥 나열하지 않고 **기한 5버킷**으로 묶는다. 이게 "직관적"의 정체다.

```
지연 (text-danger)  →  오늘 (text-accent-teal)  →  이번 주  →  나중  →  기한 없음
```

```ts
function bucketFor(t: Task): Bucket {
  if (!t.due_date) return "no_date";
  const diffDays = 일수차(startOfDay(t.due_date), startOfDay(오늘));
  if (diffDays < 0)  return "overdue";
  if (diffDays === 0) return "today";
  if (diffDays <= 7)  return "this_week";
  return "later";
}
```

**날짜 비교는 반드시 `startOfDay()` 로 자정 기준을 맞춘다.** 시각까지 비교하면
"오늘 마감"인데 오전에 이미 `overdue` 로 빠진다. 가장 흔한 버그.

완료된 항목은 미리보기에서 제외(`t.status !== "done"`), 헤더의 `전체 N건` 에는 포함.

## 6. 「내 활동」 페이지 — 자기 페이지에서 다 확인

📄 `reference/src/pages/me-posts.tsx` (라우트 `/me/posts`)

한 페이지에서 **내가 만든 모든 것**을 종류별로 보여준다.

```
내 활동
──────────────────────────
인사이트   (내 것만 필터)      → InsightCard 그리드
글쓰기     (임시저장 포함)      → WritingCard
회의록     (내가 작성한 것)     → 행 리스트
챌린지 노트                     → ReadingNoteBadges
내 할일    (담당자 = 나)        → 상태 라벨 + 기한
비전보드                        → 카드
```

구현은 **기존 조회 함수를 그대로 재사용하고 클라이언트에서 필터**한다.
전용 쿼리를 새로 만들지 않는다.

```ts
const { data: insights } = useAsync(
  () => getWorkspaceInsights(workspace.id, user.id), [workspace?.id, user?.id]);
// 렌더할 때 (insights ?? []).filter(i => i.user_id === user.id)

const { data: myTasks } = useAsync(
  () => getTasks({ workspaceId: workspace.id, assigneeId: user.id }), […]);
```

`getTasks({ workspaceId, assigneeId, openOnly })` 처럼 **필터 인자를 받는 만능
조회 함수 하나**를 두면, 홈·할일목록·내 활동·멤버 상세가 전부 같은 함수를 쓴다.
📄 `reference/src/lib/data/tasks.ts` 상단.

상태 라벨은 한국어 상수로:

```ts
const STATUS_LABEL: Record<string, string> = {
  todo: "대기", in_progress: "진행 중", done: "완료",
};
```

## 7. 멤버 상세 — "이 사람이 뭘 하고 있나"

밋업의 `/members/:id` 는 프로필 + 참석 이력 중심인데, **이식할 때 여기에
아래 두 섹션을 추가하는 걸 권장**한다. 재료가 이미 다 있다.

```tsx
// ① 이 멤버가 담당인 미완료 할일
const { data: theirTasks } = useAsync(
  () => getTasks({ workspaceId: workspace.id, assigneeId: memberId, openOnly: true }),
  [workspace?.id, memberId],
);

// ② 이 멤버의 최근 활동 — 전체 피드를 가져와 클라이언트 필터
const { data: acts } = useAsync(
  () => getWorkspaceActivities(workspace.id, 100), [workspace?.id]);
const mine = (acts ?? []).filter(a => a.user_id === memberId).slice(0, 10);
<ActivityFeed activities={mine} bare title="최근 활동" />
```

> 규모가 커지면 `getUserActivities(workspaceId, userId, limit)` 를
> `activities_user_idx` 인덱스를 타도록 따로 만든다. 인덱스는 이미 007에 있다.
