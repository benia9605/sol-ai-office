# 05 · 할일 — 목록 · 상세 · 배정 · 완료 · 소셜

밋업의 할일은 **자기 페이지를 가진 1급 자원**이다. 체크리스트 항목이 아니다.
그래서 본문(에디터)·첨부·좋아요·댓글·답글이 다 붙고, 회의록에도 연결된다.

## 1. 스키마 요점

```ts
type Task = {
  id, workspace_id,
  title, description,          // description = 에디터 HTML
  status: "todo" | "in_progress" | "done",
  priority: "low" | "medium" | "high",
  due_date: string | null,     // timestamptz
  assignee_id: string | null,  // 담당자 — 알림 받는 사람
  created_by: string,          // 작성자 — 배정한 사람
  meeting_id: string | null,   // 어느 일정에서 나온 할일인가
  note_id: string | null,      // 어느 회의록에 묶인 할일인가
  category: string | null,
  created_at, completed_at: string | null,
};
```

**절대 헷갈리면 안 되는 두 쌍**

| | 뜻 | 알림 |
| --- | --- | --- |
| `created_by` | 배정한 사람 (작성자) | 남이 좋아요/댓글 달면 받음 |
| `assignee_id` | 실행할 사람 (담당자) | **배정 즉시 받음** |

| | 뜻 |
| --- | --- |
| `meeting_id` | 이 할일이 나온 **일정** |
| `note_id` | 이 할일이 묶인 **회의록** |

`note_id` 가 있어도 `meeting_id` 를 따로 저장한다. 중복처럼 보이지만
"일정 상세에서 그 일정의 할일 전부"를 회의록 조인 없이 뽑기 위한 의도적 비정규화다.

**할일은 회의록의 자식이 아니다.** 회의록을 지워도 할일은 남는다 (`on delete set null`).
회의 없이 그냥 만든 할일도 정상이다 (둘 다 `null`).

## 2. 데이터 레이어 — 만능 조회 함수 하나

```ts
export async function getTasks({ workspaceId, assigneeId, openOnly = false }): Promise<Task[]>
```

화면 4개가 이 함수 하나를 쓴다.

```ts
getTasks({ workspaceId })                                   // 할일 목록 전체
getTasks({ workspaceId, assigneeId: user.id })              // 내 활동 페이지
getTasks({ workspaceId, assigneeId: user.id, openOnly:true })// 홈 「내 할일」
getTasks({ workspaceId, assigneeId: memberId, openOnly:true })// 멤버 상세
getTasksForNote(noteId)                                     // 회의록 상세
```

화면별 전용 쿼리를 만들지 마라. **필터 인자를 받는 함수 하나 + 클라이언트 정렬**이
유지보수 비용이 압도적으로 싸다.

### 정렬 규칙

```ts
function compareForBoard(a, b) {
  if (a.status === "done" && b.status !== "done") return 1;   // 완료는 항상 아래
  if (b.status === "done" && a.status !== "done") return -1;
  return b.created_at.localeCompare(a.created_at);            // 최신 위
}
```

## 3. 생성 — 배정 시 담당자에게만 알림

```ts
const { data } = await supabase.from("tasks").insert({...}).select().single();

if (data?.assignee_id) {
  const name = await getActorName(createdBy);
  await notify({
    type: "new_task",
    workspace_id: data.workspace_id,
    actor_id: createdBy,                      // ← 본인이 본인에게 만들면 자동 제외
    title: "📝 새 할일",
    body: `${name} 님이 회원님께 「${data.title}」을 배정했어요.`,
    url: `/tasks/${data.id}`,
    tag: `task-${data.id}`,
    target_user_ids: [data.assignee_id],      // ← 담당자 1명에게만
  });
}
```

- **담당자 미지정이면 알림을 아예 안 보낸다.** 조건문 위치 주의.
- `actor_id === assignee_id` 면 Edge Function ③단계에서 걸러져 `sent: 0` 이 된다.
  이게 정상 동작이다. "내가 나에게 만든 할일" 알림은 소음이다.

## 4. 수정 — 완료 전환 감지가 핵심

```ts
// ① 이전 상태를 먼저 조회 (전환 감지용)
const { data: prev } = await supabase.from("tasks")
  .select("status, completed_at").eq("id", id).maybeSingle();
const wasDone = prev?.status === "done";

// ② completed_at 자동 관리 — 화면에서 넘기지 않는다
if (patch.status === "done" && !prev?.completed_at) finalPatch.completed_at = new Date().toISOString();
else if (patch.status && patch.status !== "done") finalPatch.completed_at = null;

// ③ done 으로 "전환"된 경우에만 활동 기록 + 전체 알림
if (!wasDone && updated.status === "done") {
  await recordActivity({ action: "completed_task", … }, actor);
  await notify({ type: "task_completed", actor_id: actor,
    title: "✅ 할일 완료",
    body: `${name} 님이 「${updated.title}」을 완료했어요.`,
    url: `/tasks/${updated.id}`, tag: `task-${updated.id}-done` });   // target 없음 = 전체
}
```

**`wasDone` 체크를 빼면** 완료된 할일을 편집 저장할 때마다 "완료했어요" 알림이
매번 나간다. 이식할 때 실제로 자주 빠지는 부분이다.

### `actorId` 를 명시적으로 넘겨라

```ts
export type UpdateTaskOpts = { actorId?: string };
const actor = opts?.actorId ?? updated.assignee_id ?? updated.created_by;
```

폴백 순서가 있지만, **편집 화면에서는 반드시 `{ actorId: user.id }` 를 넘긴다.**
안 넘기면 "담당자가 완료했다"로 잘못 기록되고, 본인 제외 필터도 엉뚱하게 걸린다.

```ts
await updateTask(task.id, patch, { actorId: userId });
```

## 5. 할일 소셜 — 대상은 작성자 + 담당자

```ts
function taskNotifyTargets(task, actorId: string): string[] {
  return [task.created_by, task.assignee_id]
    .filter((id): id is string => !!id && id !== actorId);
}
```

- 좋아요 = "확인했어요 / 응원" 신호. 담당자에게 특히 의미가 있다.
- 댓글 = 진행 논의. 작성자·담당자 둘 다 알아야 한다.
- 답글 = 부모 댓글 작성자에게만 (01 문서 3장).

세부 구현은 01 문서, 코드는 📄 `reference/src/lib/data/tasks.ts` 하단.

## 6. 목록 페이지 `/tasks`

📄 `reference/src/pages/tasks.tsx`

```
Tasks
할일                                            [+ 할일 추가]
오늘의 한 칸을 차근차근 채워봐요.
────────────────────────────────────────────────────────────
전체 24    내 할일 7                       12건  [필터⚙]
────────────────────────────────────────────────────────────
☑ 예산안 초안 작성   ↗회의록   미완료   담당 · (av)김대표   8/24
☐ 경쟁사 리서치                미완료   담당 · (av)박이사   8/20  ← danger
```

**구조 규칙**

1. **탭은 「전체 / 내 할일」 둘.** 카운트를 옆에 붙인다.
   `?scope=mine` 쿼리로 진입하면 「내 할일」 탭이 선택된 채 열린다 —
   홈의 「내 할일 전체 보기」가 이 링크를 쓴다.
2. **필터는 접힌 서랍.** 아이콘 버튼 하나, 활성 필터 개수를 배지로.
   기본 상태에서 화면이 컨트롤로 덮이지 않는다.
3. **탭 nav 의 `border-b` 와 첫 행이 곧장 맞닿는다.** 사이에 `pt-8` 같은 여백을
   넣지 않는다 (밋업에서 여러 번 지적된 패턴).
4. **페이저**로 자르되 카운트는 전체 기준.
5. 빠른 추가는 **인라인 폼**(`addOpen` 토글). 모달 아님.

### 행 디자인 — 반응형 재배치가 포인트

📄 `reference/src/features/tasks/task-row.tsx`

- **행 전체가 `<Link>`** → 상세로.
- **체크박스만 예외** — `e.preventDefault(); e.stopPropagation();` 으로 링크 이동을
  막고 상태만 토글한다. 이걸 안 하면 체크하려다 페이지가 넘어간다.
- 체크박스는 사각형(`size-5 border`). 완료 시 `bg-accent-teal` + `✓`.
- **모바일**: 담당/기한이 제목 아래 두 번째 줄로 (`sm:hidden`).
  **데스크탑**: 오른쪽 고정폭 열로 (`hidden sm:flex w-40` / `w-28`).
  같은 정보를 폭에 따라 재배치 — 가로 스크롤이 절대 생기지 않는다.
- 지연은 `text-danger`, 완료 행은 `bg-surface-muted` + `line-through`.
- 회의록에서 나온 할일이면 제목 옆에 `↗ 회의록` 링크 (`stopPropagation` 필수).

## 7. 상세 페이지 `/tasks/:id` — 이식의 표준형 ★

📄 `reference/src/pages/task-detail.tsx` — **이 파일 하나가 05·04·01 문서를
전부 조립한 예시다.** 새 자원 상세를 만들 때 이걸 복사해서 시작하라.

```
← 할일                              [편집] [작업 완료] [삭제]
────────────────────────────────────────────────────────────
예산안 초안 작성                                  ← h1 (완료면 line-through)

┌──────────┬──────────┬──────────┐   ← grid gap-px bg-surface-muted
│ 담당자    │ 기한      │ 작성자    │     border 1개로 3칸 구분선을 만드는 기법
│ (av)김대표│ 8월 24일  │ (av)박이사│
└──────────┴──────────┴──────────┘

[회의록] 3분기 전략 회의                            ›   ← 연결 회의록 행

내용
(RichRender)

첨부 · 2
…

──────────────────────────────────────────────  ← LikeCommentBlock
[♥ 3]                                    댓글 5
```

**뷰 ↔ 편집은 같은 URL 에서 `mode` state 토글** (원칙 1). 편집 모드는:

```
Editing Task
[제목 인풋 — h1 크기 그대로]
담당자 [select]        기한 [date]
회의록 연결 [select — "— 연결 안 함 —" 포함]
내용 [RichEditor minHeight=280]
첨부 [AttachmentsSection canManage]
        [취소] [임시저장] [수정 저장] [수정 + 할일 완료]
```

**「수정 + 할일 완료」 버튼**을 꼭 넣어라. 실제 사용 흐름이 "결과를 적고 완료 처리"
인데, 저장 후 다시 완료 버튼을 찾게 하면 마찰이 크다.

권한:

```ts
const canManage =
  task.created_by === user.id || task.assignee_id === user.id ||
  myRole === "owner" || myRole === "admin";
const canModerate = myRole === "owner" || myRole === "admin";  // 남의 댓글 삭제
```

메타 3칸의 `grid gap-px bg-surface-muted border border-line` + 각 셀 `bg-surface` —
**border 를 셀마다 그리지 않고 배경색 틈으로 구분선을 만드는** 기법. hairline 원칙에
맞고 이중선이 안 생긴다. 다른 자원 상세에서도 그대로 쓴다.

## 8. 진행률

📄 `reference/src/components/task-progress.tsx`

```tsx
<TaskProgress done={done} total={total} />          // 박스형
<TaskProgress done={done} total={total} compact />  // 리스트 행 안
```

**대원칙: 진행률은 저장하지 않는다.** 매번 배열에서 센다.
`total === 0` 이면 아무것도 렌더하지 않는다 (0/0 = NaN% 방지).

바는 `h-1 bg-line` 위에 `bg-accent-teal` — 진행률은 액센트 색을 쓰는 세 상황 중
"완료/긍정"에 해당한다.
