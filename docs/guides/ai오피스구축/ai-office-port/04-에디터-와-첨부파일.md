## 2. 공개 API — 딱 2개

```tsx
import { RichEditor, RichRender } from "@/features/editor/rich-editor";

// 쓰기
<RichEditor
  value={description}
  onChange={setDescription}
  placeholder="과제 설명 / 참고 자료 / 체크리스트 등."
  minHeight={280}
/>

// 읽기
<RichRender html={task.description} />
```

**저장 형식은 HTML 문자열.** 컬럼은 `text`. JSON(ProseMirror doc) 이 아니다 —
검색·요약·미리보기 추출이 훨씬 쉽고, 뷰어가 에디터 없이도 렌더된다.

빈 에디터는 `<p></p>` 를 뱉는데 `onChange` 에서 `''` 로 정규화해 DB 를 깨끗이 유지한다.
저장할 때도 한 번 더:

```ts
description: description.trim() ? description : null,
```

## 3. 툴바 기능 (밋업 현행)

```
B  I  S  │  H1 H2 H3  │  A(글자색) H(형광)  │  ·  1.  ☑  │  "  <|>
│  🔗  🖼  ▶(유튜브)  HTML  │  클로드  질문
```

| 버튼 | 기능 | 메모 |
| --- | --- | --- |
| B / I / S | 굵게 / 기울임 / 취소선 | ⌘B·⌘I 를 **capture 단계에서 가로채** 브라우저 단축키 충돌 방지 |
| H1~H3 | 제목 3단계 | `StarterKit.configure({ heading: { levels: [1,2,3] } })` |
| A / H | 글자색 / 형광펜 팝오버 | 마지막 사용 색 기억 → ⌘⇧E / ⌘⇧H 로 재적용 |
| · / 1. / ☑ | 글머리 / 번호 / **체크리스트** | 체크리스트가 회의록에서 제일 많이 쓰인다 |
| `"` | 인용 (발언자 지정 가능한 커스텀 blockquote) | `data-speaker` 속성 지원 |
| `<\|>` | 코드 블록 | |
| 🔗 | 링크 | **글자를 선택해야 활성.** 이미 링크면 누르는 즉시 해제 |
| 🖼 | 이미지 업로드 | Storage 업로드 후 URL 삽입 (아래 5장) |
| ▶ | 유튜브 임베드 | URL 만 단독으로 **붙여넣어도** 자동 임베드 |
| HTML | 원본 HTML 블록 삽입 | ★ 아래 6장 |
| 클로드 / 질문 | 정해진 인용블록 **틀** 삽입 | AI 호출 아님. 대화 기록/QA 서식 |

**툴바는 sticky** 다. 본문이 길어져도 항상 보인다. 본문 영역은 `minHeight` 부터
시작해 최대 높이까지 늘고 그 이후엔 내부 스크롤.

에디터 **패딩/여백을 클릭해도 포커스가 잡힌다** (ProseMirror 밖을 눌렀을 때
`focus('end')`). 사소해 보이지만 모바일에서 체감이 크다.

### 붙여넣기 3분기

```
① YouTube URL 단독      → 임베드 노드로 삽입
② 마크다운처럼 생긴 텍스트 → marked 로 HTML 변환 후 삽입
③ HTML                  → Tiptap 기본 동작
```

`looksLikeMarkdown()` 이 `#`, `- `, `**`, 표 문법 등을 휴리스틱으로 판별한다.
ChatGPT/Claude 답변을 그대로 붙여넣으면 서식이 살아난다 — 실사용에서 매우 자주 쓰인다.

## 4. `RichRender` — 읽기 쪽

```tsx
export function RichRender({ html }: { html: string }) { … }
```

- 내부적으로 `dangerouslySetInnerHTML` + `.prose-meetup` 스타일.
- `toRenderableHtml()` 이 입력이 HTML 인지 평문인지 판별해서, 평문이면
  이스케이프 + `<br>` 처리. **DB 에 옛 평문 데이터가 섞여 있어도 안 깨진다.**
- raw HTML 블록(`data-raw-html`)은 **sandbox iframe 으로 격리 렌더**하고
  `MutationObserver` 로 멱등 hydrate 한다 (React 리렌더에 지워져도 자동 복구).

> ⚠️ **보안** — 밋업은 6인 비공개 모임이라 `allow-scripts allow-same-origin` 으로
> 사용자 HTML/스크립트를 살려둔다. **이식 대상 앱이 외부 공개거나 신뢰 범위가
> 넓다면 반드시 새니타이즈하거나 `allow-same-origin` 을 빼야 한다.**
> 결정 기준과 대안 설정이 `docs/guides/editor/rich-editor-html-viewer.md` 6장에
> 정리돼 있다. **이식 전에 이 결정을 먼저 하라.**

## 5. 이미지 — 에디터 안 업로드

툴바 🖼 → 파일 선택 → Storage 업로드 → public URL 을 `Image` 노드로 삽입.
`accept="image/png,image/jpeg,image/gif,image/webp"`.
같은 파일을 다시 고를 수 있도록 `onChange` 에서 `e.target.value = ""` 로 초기화한다.

**첨부파일(6장)과는 다른 경로다.**

| | 에디터 이미지 | 첨부파일 |
| --- | --- | --- |
| 위치 | 본문 흐름 안 | 본문 아래 별도 섹션 |
| 버킷 | public | **private** (`attachments`) |
| URL | public URL | 1시간 짜리 signed URL |
| 목적 | 읽는 흐름의 일부 | 다운로드용 자료 |

## 6. 첨부파일

📄 `reference/src/features/attachments/attachments-section.tsx`

```tsx
<AttachmentsSection
  workspaceId={workspace.id}
  refType="task"          // 'meeting' | 'meeting_note' | 'task' | 'insight'
  refId={task.id}
  canManage={canManage}   // false 면 목록만 (추가/삭제 버튼 숨김)
/>
```

**폴리모픽 한 테이블**로 모든 자원의 첨부를 담는다 (활동 피드와 같은 발상).

```sql
create table public.attachments (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid not null references public.workspaces(id) on delete cascade,
  ref_type     text not null,      -- 'meeting' | 'meeting_note' | 'task' | 'insight'
  ref_id       uuid not null,
  storage_path text not null,
  filename     text not null,
  mime         text,
  size_bytes   bigint,
  uploaded_by  uuid not null references auth.users(id) on delete cascade,
  created_at   timestamptz not null default now()
);
create index attachments_ref_idx on public.attachments(ref_type, ref_id);
```

### Storage 경로 컨벤션이 곧 RLS 다

```
attachments/{workspace_id}/{ref_type}/{ref_id}/{uuid}-{sanitized_filename}
avatars/{user_id}/{uuid}.{ext}
```

첫 번째 폴더가 권한 판정 키다.

```sql
create policy "attachments_read_member" on storage.objects
  for select to authenticated using (
    bucket_id = 'attachments'
    and public.is_workspace_member(((storage.foldername(name))[1])::uuid)
  );
```

📄 전체 정책: `reference/supabase/migrations/011_storage.sql`

파일명은 `sanitize()` 로 정리한다 — NFKD 정규화 + `[^\w.\-]` 제거 + 80자 컷.
한글 파일명이 Storage 에서 깨지는 문제를 여기서 막는다. 원본 이름은 `filename`
컬럼에 따로 보관해 UI 에는 그대로 보여준다.

### 다운로드는 signed URL

```ts
const { data } = await supabase.storage
  .from("attachments").createSignedUrl(attachment.storage_path, 3600);
```

private 버킷이라 public URL 이 없다. **뷰어를 열 때마다 1시간짜리를 새로 발급**한다.

### 삭제는 2단계, 업로드 실패는 롤백

```ts
// 삭제: Storage 먼저 → 테이블 행
await supabase.storage.from("attachments").remove([attachment.storage_path]);
await supabase.from("attachments").delete().eq("id", attachment.id);

// 업로드: Storage 성공 후 insert 실패하면 고아 파일 정리
if (error || !data) {
  await supabase.storage.from("attachments").remove([path]);
  return null;
}
```

### 뷰어 (모달을 쓰는 정당한 예외)

📄 `reference/src/features/attachments/attachment-viewer.tsx`

| 종류 | 렌더 |
| --- | --- |
| PDF | `<iframe src={signedUrl}>` |
| 이미지 | `<img>` (`max-h-[80vh] object-contain`) |
| Office (doc/docx/ppt/pptx/xls/xlsx) | `view.officeapps.live.com/op/embed.aspx?src=…` |
| 그 외 | "새 탭에서 열기 / 다운로드" 버튼 |

Office 뷰어는 **URL 이 외부에서 fetch 가능해야** 한다 — signed URL 이라 동작한다.
Esc 로 닫히고, 열려 있는 동안 `body` 스크롤을 잠근다.

업로드 제한은 클라이언트에서 `20 * 1024 * 1024` 로 막는다 (문구: "20MB 이하 파일만 가능해요.").

## 7. 임시저장 (수동)

긴 본문을 쓰는 화면(할일 편집 · 회의록 작성/편집 · 인사이트)엔 임시저장을 붙인다.

📄 `reference/src/lib/use-draft.ts` (48줄) + `reference/src/features/common/draft-bar.tsx`

```tsx
const { draft, save, clear, savedAt } = useDraft<TaskDraft>(`task-draft:${task.id}:${userId}`);
const [restored, setRestored] = useState(false);

{draft && !restored && (
  <DraftRestoreBanner onRestore={applyDraft} onDiscard={() => { clear(); setRestored(true); }} />
)}
…
<DraftSaveButton onSave={() => save({ title, assigneeId, dueDate, description, noteId })}
                 savedAt={savedAt} disabled={busy} />
```

**설계 결정: 자동 저장을 하지 않는다.**

- 자동 저장은 "내가 저장했나?" 를 모호하게 만들고, 실수로 지운 내용까지 덮어쓴다.
- 대신 **버튼을 누른 순간만** localStorage 에 넣고 `임시저장됨` 을 표시한다.
- 실제 저장에 성공하면 `clear()`.
- 키는 반드시 **문서 + 사용자별**: `task-draft:{taskId}:{userId}`.
  공용 키를 쓰면 다른 문서를 열었을 때 남의 초안이 튀어나온다.

버튼 배치 순서는 밋업 관례를 따른다:
`[임시저장(좌측 끝)] … [취소] [삭제] [수정 저장] [수정 + 완료]`
