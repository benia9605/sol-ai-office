# 07 · 기록 · 인사이트 — 「게시물형 자원」 표준형

할일·회의처럼 구조가 특수한 자원을 뺀 나머지 — 인사이트, 글쓰기, 독서/챌린지 노트,
공지 — 는 전부 **같은 모양**이다. 하나를 만들면 나머지는 복사다.

> **밋업의 실제 자원 → 이식 대상 앱 매핑 예시**

> `notices`(공지) → 오피스 앱의 「기록」 / 「인사이트」 / 「자료」 계열.
> 이름만 바꾸면 된다. 구조는 아래 하나.

## 1. 게시물형 자원의 공통 골격

```ts
type Post = {
  id, workspace_id,
  user_id: string,             // 작성자
  title: string,
  content: string | null,      // 에디터 HTML
  source: string | null,       // 출처 (선택)
  tags: string[],              // text[] 컬럼
  is_shared: boolean,          // 모임 공유 여부 (숨김 토글)
  status: "draft" | "published",
  created_at, updated_at,
};
```

여기에 항상 붙는 것:

```
{name}_likes     (post_id, user_id) 복합 PK
{name}_comments  (+ parent_id)
attachments      ref_type = '{name}'
activities       action = 'created_{name}' | 'liked_{name}' | 'commented_{name}'
```

라우트도 항상 같은 3개:

```
/{name}s          목록
/{name}s/new      작성    ← 페이지 (모달 아님)
/{name}s/:id      상세    ← 여기서 편집 모드 토글
```

## 2. `XWithMeta` — 목록에 필요한 걸 한 쿼리로

목록 화면에는 작성자 · 좋아요 수 · 댓글 수 · 내가 눌렀나가 다 필요하다.
N+1 을 피하려면 **임베드 select 한 방**이다.

```ts
export type InsightWithMeta = Insight & {
  author: AuthorRef | null;
  like_count: number;
  comment_count: number;
  liked_by_me: boolean;
};

const embedSelect =
  "*, author:user_profiles!insights_user_id_fkey(user_id, name, email, avatar_url, company, position)," +
  " likes:insight_likes(user_id), comments:insight_comments(id)";

// 매핑
like_count:   row.likes?.length ?? 0,
comment_count: row.comments?.length ?? 0,
liked_by_me:  row.likes?.some(l => l.user_id === currentUserId) ?? false,
```

`likes:insight_likes(user_id)` 는 **좋아요 행 전체가 아니라 user_id 만** 가져온다.
개수를 세면서 동시에 "내가 눌렀나"까지 판정할 수 있다. 쿼리 하나로 세 가지 해결.

### 3단 폴백 — RLS 가 꼬여도 화면이 안 죽는다

📄 `reference/src/lib/data/insights.ts` 의 `getWorkspaceInsights`

```
① 임베드 전체 (author + likes + comments)
      ↓ 실패하면 (RLS 재귀 등)
② author 만 조인
      ↓ 실패하면
③ bare select (`*`)  — 작성자/카운트는 0, 그래도 글은 보인다
```

각 단계에서 `error.code / message / details / hint` 를 콘솔에 남긴다.
**이식 초기에 RLS 를 잡을 때 이 로그가 결정적이다.** 화면이 하얗게 죽지 않고
"글은 보이는데 작성자가 없다" 로 나타나 원인 범위가 즉시 좁혀진다.

## 3. 생성 — 발행일 때만 알림

```ts
const filled = { is_shared: true, status: "published" as const, ...input };
const { data, error } = await supabase.from("insights").insert({...filled, user_id}).select().single();

if (error) {
  console.error("[insights] createInsight failed", {message, code, details, hint, payload});
  throw new Error(`인사이트 저장에 실패했습니다 (${error.code ?? "unknown"}): ${error.message}`);
}

if (data.is_shared && data.status === "published") {
  await recordActivity({ action: "shared_insight", resource_type: "insight",
                         resource_id: data.id, metadata: { title: data.title } }, userId);
  await notify({ type: "new_insight", actor_id: userId,
    title: "💡 새 인사이트",
    body: `${name} 님이 「${data.title}」 인사이트를 공유했어요.`,
    url: `/insights/${data.id}`, tag: `insight-${data.id}` });
}
```

**임시저장(draft)이나 비공개(is_shared=false)면 알림도 활동 기록도 안 나간다.**
이 조건을 빼면 초안 저장할 때마다 전원에게 푸시가 간다.

> 생성 함수는 조회와 달리 **에러를 삼키지 않고 throw** 한다.
> 저장 실패는 사용자가 즉시 알아야 하기 때문. (알림 실패와는 반대)

## 4. 좋아요 · 댓글 — 01 문서와 동일

인사이트 기준 수신자는 **작성자 1명** (할일처럼 담당자가 없으므로).

```ts
if (ins.user_id !== userId) {
  await notify({ type: "like", actor_id: userId, title: "👏 좋아요",
    body: `${name} 님이 「${ins.title}」 인사이트에 좋아요를 눌렀어요.`,
    url: `/insights/${ins.id}`, tag: `insight-like-${ins.id}-${userId}`,
    target_user_ids: [ins.user_id] });
}
```

좋아요/댓글 모두 `recordActivity` 도 같이 남긴다 (`liked_insight` / `commented_insight`,
댓글은 `metadata.excerpt` 에 앞 80자).

## 6. 목록 페이지 — 카드 그리드

📄 `reference/src/components/insight-card.tsx`

```tsx
<Link to={`/insights/${insight.id}`}
      className="h-full flex flex-col border border-line p-6 hover:border-foreground transition-colors">
  <header>… (av) 작성자 / 소속 · 직함 … 날짜</header>
  <h3 className="mt-5 text-lg font-medium leading-snug">{title}</h3>
  <p className="mt-3 text-sm leading-[1.85] text-foreground-muted line-clamp-3">{본문 요약}</p>
  <ul>…태그…</ul>
  <footer>♥ {like_count} · 💬 {comment_count}</footer>
</Link>
```

- **카드 = 링크.** 그림자 없음, hover 에 `border-foreground` 만.
- `h-full flex flex-col` + 본문 `flex-1` → 그리드에서 카드 높이가 맞는다.
- 미리보기는 `line-clamp-3`.

### 본문이 HTML 이라 미리보기가 깨질 때

`content` 는 에디터 HTML 이라 카드에 그대로 넣으면 태그가 보인다.
밋업은 미리보기 추출을 별도 유틸로 뺀다 —
📄 `reference/src/lib/note-preview.ts` 는 회의록용(아젠다 앞 3개 → 본문 첫 줄,
마크다운 머리표 제거)이다. 게시물형에는 아래 정도로 충분하다.

```ts
export function toPreviewText(html: string, max = 140): string {
  const text = html.replace(/<[^>]+>/g, " ").replace(/\s+/g, " ").trim();
  return text.length > max ? `${text.slice(0, max)}…` : text;
}
```

## 7. 숨김(`is_shared`) 과 임시저장(`status`)

두 개는 **다른 축**이다. 헷갈리면 안 된다.

| | 뜻 | 누가 바꾸나 |
| --- | --- | --- |
| `status: draft/published` | 아직 안 쓴 글인가 | 작성자 |
| `is_shared: true/false` | 발행했지만 지금은 안 보이게 | 작성자 **또는 관리자** |

- `draft` → 목록에서 **본인에게만** 보인다. 홈 「확인이 필요한 일」의 초안 카운트에 잡힌다.
- `is_shared: false` → 관리자 모더레이션 수단. 삭제 대신 숨김.

목록 쿼리에서:

```ts
.filter(i => i.is_shared || i.user_id === currentUserId)
```
