## 🔀 방향 전환 (2026-08-07) — AI Office = 회사 운영 OS (ERP 아님)

**원칙:**
- **시목앱 = System of Record** — 제품·재고·주문·판매·매입 등 ERP 데이터의 소유자.
- **AI Office = System of Intelligence** — 분석·판단·업무 운영. ERP 데이터를 **소유하지 않고 조회만**.

**바뀐 것:**
- **Products / Sales Daily** = 입력 시스템 → **외부앱 연동 전제의 조회·분석 레이어**로 전환.
- 지금 CRUD는 **삭제하지 않고 Compatibility Mode(임시 수기 입력)로 유지**. `src/config/dataSource.ts`의 `ERP_SOURCE`가 `'manual'`(수기)/`'simok_api'`(연동) 분기. 시목 API 연결 시 `'simok_api'`로 바꾸면 서비스가 외부 데이터를 읽고, AI Office 쓰기는 자동 차단(`assertWritable`).
- 서비스에 `fetchProductsFromSimok`/`fetchSalesFromSimok` **스텁(seam)** + 뷰 상단 **Compatibility 배너** + 외부 모드 시 입력 UI 숨김.
- **그대로 유지(AI Office 고유 = System of Intelligence):** Tasks · Content Items · Content Metrics · Company Memory. (이건 AI Office가 소유·생성하는 데이터.)

**Phase 7(Context Engine) 설계 기준:** ERP 데이터는 소유하지 않고 **필요한 것만 조회해 Context 구성**. contextRecipes에서 `products`/`sales`는 "시목 API 조회" 소스로 정의(연동 후).

**변경 파일:** `src/config/dataSource.ts`(신규) · `products.service.ts` · `salesDaily.service.ts`(소스 분기·쓰기 가드·외부 스텁) · `views.tsx`(ErpSourceBanner·입력 UI 게이팅·"조회·분석" 리프레이밍).

## Phase 1.5 — Task 구조 확장 (category · source · completed_at) · ✅ 완료 · 🟢 CEO 승인(2026-08-04)

> **보완(승인 후):** 레거시 `tasks.source=NULL` 행은 앱에서 **manual로 해석**(`toTaskItem`에서 `row.source ?? 'manual'`) → 필터·분석에서 NULL 누락 방지. 전체 백필은 하지 않음(불필요).

**목차:** 1.5-1 source 컬럼 추가 · 1.5-2 category 9종 UI · 1.5-3 completed_at 완료경로 보강 · 1.5-4 Workspace Activity seam(구조만)

> **왜:** 나중에 "어떤 기능에서 생성된 Task인지" 추적 + 완료율·리드타임 분석 기반 데이터.
> **파이프라인:** ACTION(생성) + LEARNING(완료 분석).
> **오픈 전에 맞는가:** YES — 데이터는 초기부터 쌓여야 나중 분석이 가능(스키마를 먼저 잡아두는 게 저비용).

**발견:** `completed_at`·`category`는 **이미 tasks 컬럼에 존재**(`updateTaskStatus`가 완료 시 completed_at 자동 저장, `tasks.service.ts`). → **실제 신규 DB 컬럼은 `source` 하나뿐.**

- **category(text):** 콘텐츠·제품·쇼룸·촬영·회의·운영·마케팅·CS·AI 9종 드롭다운(추가·수정 폼). 카드에 카테고리 칩 표시.
- **source(text):** manual·content·decision·memory·campaign·ai. 대표 수동 추가는 `source='manual'` 자동. (콘텐츠·결정·AI가 만들 땐 각 기능이 지정 예정.)
- **completed_at:** 상태 순환 경로는 기존 `updateTaskStatus`가 처리. **상세 팝업 경로(updateTask)에도 보강** — 완료로 바꾸면 시각 기록, 해제하면 null.
- **AI 판별:** `isAiTask(t) = category==='🤖 AI' || source==='ai'` 로 견고화(AI 필터).
- **Workspace Activity:** 구조만 고려 — Task 생성/수정/완료/삭제 시 `workspace_activities`에 이벤트를 남길 seam 위치 식별(실제 로깅 호출은 **후속 구현**, Backlog).

**핵심 코드 (completed_at 완료경로 보강 — useTasks.updateTask):**

```ts
if (patch.status !== undefined) {
  dbPatch.status = toDbStatus(patch.status);

```

