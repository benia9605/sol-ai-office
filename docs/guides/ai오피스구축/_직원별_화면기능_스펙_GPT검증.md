## 공통 현황 (지금 어디까지 되어 있나)

- **채용 / 수동 실행('지금 실행') / 리포트 / HITL 승인**은 됨. AI가 만든 제안(일정·할일·인사이트)을 대표가 **승인하면 실제로 등록**.
- **직원 타입별 전용 뷰(`StaffOutputView`)는 이미 10종 다 구현**돼 있음 — 단, **실제 AI 리포트(content_json)가 있을 때만** 표시됨. (API 키 없으면 데모라 전용 뷰 대신 샘플만)
- **저장함(⭐ 보관함)**: 좋은 산출물을 저장 가능.
- ⚠️ **미완 공통 3가지 (GPT 검증 대상):**
  1. 직원 **상세 상단 '산출물 영역'은 설명 placeholder** (실제 작업 화면이 아니라 안내문).
  2. **실제 발행/저장 액션 일부 미완** — 예: SNS 실제 발행, 상세페이지 HTML을 편집·저장, CS 답변을 실제 채널로 전송 등은 아직 "복사"까지.
  3. **입력(직접 시키기)은 텍스트 위주** — 이미지 업로드·링크 붙여넣기 등 타입별 특수 입력은 일부만.

> 아래 각 직원의 **"목표 화면·기능"**이 GPT가 검증할 핵심입니다.

## 1. 🔍 소싱 기획자 (`sourcing` · `sourcing_brief` · research 모델)
- **역할:** "이거 팔아도 될까"를 느낌이 아니라 근거로. 트렌드·경쟁강도·마진·타겟 5축 점수 → 추천/보류/비추천.
- **지금:** `SourcingView`(의사결정 브리프) — 분석/키워드/기획 탭 + 추천여부 배지. 저장·승인 됨.
- **목표 화면·기능:** 소싱 후보를 **보관함에 쌓고**, 후보별 점수 비교, 채택 시 **제품(products) 또는 콘텐츠 아이디어로 승격**.
- **검증 포인트:** 시목은 자체 제품을 만드는 브랜드인데, "소싱(사입)" 직원이 맞나? 아니면 **"신제품 기획"**으로 재정의할지?

## 2. 📄 상세페이지 제작자 (`detail_page` · `detail_builder` · sonnet)
- **역할:** 상품 정보 → 12섹션 상세페이지(후킹→CTA), 스마트스토어 HTML.
- **지금:** `DetailBuilderView`(페이지 빌더) — 6섹션 에디터 + 섹션별 재생성 + HTML 복사.
- **목표 화면·기능:** 제품(products) 선택 → 상세 초안 생성 → **섹션별 편집·재생성 → HTML 저장/내보내기**. 완성본을 제품에 연결.
- **검증 포인트:** 시목 제품이 시목앱(SoR)에 있는데, 상세페이지 결과물을 **어디에 저장**? (AI Office 보관함 vs 시목앱 push) MVP는 복사까지면 충분한가?

## 3. 💬 CS 응대 (`cs` · `ticket_list` · sonnet)
- **역할:** 문의 붙여넣기 → 유형·긴급도 분류 + 답변 초안. FAQ·후기 대응.
- **지금:** `TicketListView`(문의 티켓) — 분류 + 답변 초안 복사.
- **목표 화면·기능:** 문의를 **티켓으로 쌓고**, 답변 초안 편집 → (미래) 실제 채널 전송, 반복 문의는 FAQ로.
- **검증 포인트:** 문의는 어디서 들어오나? (스마트스토어 톡·자사몰·인스타 DM) 수기 붙여넣기로 시작이 맞나, 아니면 특정 채널 연동 우선?

## 4. 📣 SNS 운영 (`sns` · `sns_queue` · gpt 모델)
- **역할:** 월간 캘린더 + 캡션 A/B/C + 릴스/스토리 스크립트.
- **지금:** `SnsQueueView`(발행 대기 큐) — 게시물 초안 카드(본문·해시태그·이미지 브리프) + 복사/발행 체크.
- **목표 화면·기능:** 발행 큐 ↔ **콘텐츠(content_items)와 연결** — 초안을 콘텐츠 아이디어로 보내 촬영→발행 파이프라인에 태우기. (지금 콘텐츠 메뉴가 이미 그 파이프라인)
- **검증 포인트:** SNS 직원의 '발행 큐'와 **콘텐츠 메뉴(🎬)**가 기능이 겹침 — **하나로 합칠지**(SNS 직원이 콘텐츠 아이디어를 생성) 아니면 분리 유지?

## 5. 🎯 광고 기획 (`ad` · `copy_variants` · gpt)
- **역할:** 감성·기능·가격 3각도 광고 카피 A/B + 타겟·예산 가이드.
- **지금:** `CopyVariantsView`(A/B 3세트 비교) — 헤드라인·서브·CTA 비교.
- **목표 화면·기능:** 카피 세트를 **광고 라이브러리에 저장**, 채택본을 콘텐츠/발행에 연결. 컴플라이언스(과장·최저가) 체크.
- **검증 포인트:** 지금 시목이 유료 광고를 돌리나? 안 하면 우선순위 낮춰도 되는지?

## 6. 📡 모니터링 (`monitor` · `monitor_digest` · research)
- **역할:** 경쟁사 가격·리뷰·구성 + 트렌드 주간 리포트.
- **지금:** `MonitorDigestView`(경쟁사 다이제스트) — 비교표 + 트렌드 (URL/텍스트 붙여넣기 입력).
- **목표 화면·기능:** 경쟁사/키워드를 **추적 목록으로 관리**, 변화 감지 → 대응 제안(가격/구성/메시지). 트렌드 레퍼런스를 콘텐츠로.
- **검증 포인트:** 재설계안의 **"트렌드 레이더"**(레퍼런스→시목 버전 촬영각본)와 이 직원을 통합할지? (`gpt대화.md` 재설계안 B3 참고)

## 7. 📊 분석가 (`analyst` · `metric_digest` · haiku)
- **역할:** 매출·전환·ROAS 집계·해석·이상치.
- **지금:** `MetricDigestView`(지표 다이제스트) — KPI 추이 + 이상치 + 원인 가설.
- **목표 화면·기능:** **시목 매출(sales_daily)·콘텐츠 성과(content_metrics) 실데이터를 읽어** "시목 공식"(저장률 높은 유형, 채널별 객단가 등) 리포트. → CEO 브리핑의 뇌.
- **검증 포인트:** 지금 매출·성과 데이터가 연동됐으니 **이 직원을 1순위로 실데이터 연결**할 가치가 큼 — 맞나? 어떤 지표부터?

## 8. 📸 비주얼 디렉터 (`visual` · `image_brief` · sonnet)
- **역할:** 촬영컷 리스트 + 이미지 프롬프트(미드저니/나노바나나) + 목업.
- **지금:** `ImageBriefView`(비주얼 브리프) — 프롬프트 + 목업 + 촬영컷. (이미지 생성 API 연동 훅 있음)
- **목표 화면·기능:** 콘텐츠(content_items)의 촬영컷과 연결, 프롬프트로 **실제 이미지 생성** → 콘텐츠에 첨부.
- **검증 포인트:** 실제 이미지 생성(비용 발생)까지 갈지, 프롬프트 제공까지가 MVP인지?

## 9. 🗓️ 일정 비서 (`scheduler` · `schedule_plan` · sonnet)
- **역할:** 하루·주간 타임블록 계획.
- **지금:** `SchedulePlanView`(일정 계획) — 타임블록 + 승인하면 캘린더 등록.
- **목표 화면·기능:** 오늘 할일·촬영·마감을 읽어 **하루 일정 제안 → 승인 시 일정(schedules)에 등록**.
- **검증 포인트:** 개인 '일정 비서'와 오피스 운영이 겹침 — 오피스에선 **콘텐츠 발행 캘린더 중심**으로 특화할지?

## 10. 🧭 운영 매니저 (`ops` · `ops_digest` · sonnet)
- **역할:** 전 직원 취합 → "오늘 볼 것 3개". 미완료·실행실패·중복 정리.
- **지금:** `OpsDigestView`(일일 지휘 콘솔).
- **목표 화면·기능:** 승인 대기·미배정 할일·지연·KPI 이상치를 모아 **아침 브리핑**으로. (대시보드 브리핑과 연결)
- **검증 포인트:** 이게 사실상 **CEO 브리핑 생성기** — 재설계안의 CEO 브리핑 JSON 계약(`gpt대화.md` §6)과 합칠지?

## GPT에게 묻는 것 (검증 요청)

1. **우선순위:** 10명 중 시목에 지금 가장 필요한 3명은? (개인적으론 ⑦분석가·④SNS/콘텐츠·⑩운영매니저 추천 — 이미 실데이터가 연동돼서)
2. **중복 정리:** ④SNS ↔ 🎬콘텐츠 메뉴 / ⑥모니터링 ↔ 트렌드 레이더 / ⑩운영 ↔ CEO 브리핑 — 합칠지 분리할지?
3. **재정의:** ①소싱은 "사입"이 아니라 "신제품 기획"이 맞나? ⑤광고는 지금 필요 없으면 후순위?
4. **MVP 경계:** 각 직원 "실제 발행/전송/저장"까지 갈지, "초안·복사"까지가 MVP인지?
5. **데이터 연결:** ⑦분석가를 sales_daily·content_metrics 실데이터에 먼저 연결하는 게 맞나? 어떤 지표부터?

AI Office는 **AI와 대화하는 앱**이 아니라 **AI가 회사 데이터를 읽고 자동으로 일하는 운영 시스템**입니다.

반대로,

전략 수립, 상세페이지 작성, 마케팅 기획, 콘텐츠 기획, 디자인, 광고 카피 등 **대표와 오래 대화하며 만드는 작업**은 GPT 프로젝트에서 진행합니다.

# 📎 CTO 반영 + GPT에 상세 설계 재요청 (v2 · 2026-08-16)

## 대표 확정 사항 (위 GPT 방향 수용)
- **AI Office = "AI가 데이터를 읽고 자동으로 일하는 운영 시스템"** (긴 생산 대화는 GPT 프로젝트).
- **앱에서 실사용화(실데이터·전용화면·실제 액션)할 직원 = 5명:**
  **① 분석가 ② 운영매니저 ③ 모니터링 ④ 일정비서** (GPT 지정) **+ ⑤ CS 응대** (대표 요청 — 문의 티켓·분류·답변초안·FAQ까지 운영 성격만 앱에서, 긴 상담 대화는 GPT).
- **나머지 5명**(상세페이지·SNS·광고·비주얼·소싱) = **GPT 프로젝트 전담. 앱 코드는 삭제하지 않고 유지**(채용·수동실행·보관함은 되되, 핵심 강화는 안 함).
- **구현 순서**(GPT 우선순위): 분석가 → 운영매니저 → 모니터링 → 일정비서 → CS.

## GPT에게 부탁 (이게 핵심 — 최대한 자세히!)
아래 **5명 각각**에 대해 **①UI·앱 화면 구조 ②실제 기능(입력→처리→산출→저장/연결) ③매일·매주 브리핑에 정확히 들어갈 내용**을, **CTO가 그대로 코드로 옮길 수 있을 만큼 구체적으로**(블록·카드·필드·버튼·데이터 흐름·JSON까지) 설계해 주세요. "이 앱은 AI가 자동으로 일하고 대표는 결과만 본다"는 원칙에 맞게.

> 참고(현재 앱 사실): 직원 상세 = 프로필/가이드 → (분석가만)실데이터 스냅샷 → 자동 일과(주기·시간·개별/전체 실행) → 직접시키기(모드 팝업) → 제안 액션(승인=실등록) → 보관함 → 일일 리포트(전용 산출물 뷰). 읽을 수 있는 실데이터: 매출`sales_daily`, 콘텐츠 성과`content_items`+`content_metrics`, 할일`tasks`, 일정`schedules`, 인사이트`insights`, 제품`products`, 회사기억`company_memory`.

### ① 📊 분석가 (최우선 · 이미 실데이터 스냅샷 있음)
- **현재:** 매출7/30일·주문·객단가·채널별 + 콘텐츠 저장률·공유율·유형별·top3를 화면 카드로 표시, 같은 수치를 AI 프롬프트에 주입.
- **① UI 설계 요청:** 스냅샷 위에 뭘 더? 기간 토글(7/30/90)? 전주 대비 증감 화살표? "시목 공식" 카드(저장률 높은 유형·채널별 객단가)? 이상치 하이라이트 배치?
- **② 기능:** 어떤 지표가 어떤 임계를 넘으면 "이상치"로 잡고, 어떤 검증 액션(→할일 제안)으로? 
- **③ 브리핑:** 아침 KPI 브리핑에 **시목에 진짜 중요한 지표 5개**(순서 포함) + 신호등(🟢🟡🔴) 기준 + "오늘 볼 것 한 줄 결론" 형식을 정의.
