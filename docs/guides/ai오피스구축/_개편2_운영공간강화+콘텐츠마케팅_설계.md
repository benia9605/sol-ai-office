# Part A. 워크스페이스 = 소규모 회사 운영공간

> 목표: 시목(쏠+민석)처럼 **둘이서** — 그리고 나머지 1인 워크스페이스는 혼자서 — 업무·스케줄·앞으로 할 것을 **직접 적고 나눠 갖는** 공간.

## A1. 오피스 할일 — 수동 CRUD + 담당자 (★최우선)

**목적:** 오피스 할일 메뉴에서 직접 추가/수정/삭제/담당자 배정. AI 직원이 만든 할일(`category:'🤖 AI'`)과 **한 목록에서** 공존.

**현재:** `TodosView`(`views.tsx:277`)는 읽기 전용. `useTasks().add/updateTask/remove`는 이미 존재.

**설계:**
- **추가 폼(인사이트/기록 뷰와 동일 패턴):** `＋ 할일 추가` 버튼 → 인라인 폼. 필드: 제목(필수) · 우선순위(높음/보통/낮음) · 마감일(선택) · **담당자(멤버 드롭다운, 선택)**. `add({ title, priority, dueDate, assigneeId, workspaceId: activeWorkspaceId })`.
- **담당자 드롭다운:** `fetchMembers(workspaceId)`로 멤버 로드(`MembersView`가 이미 사용). 1인 워크스페이스면 담당자 필드 자체를 숨긴다.
- **상세/수정:** 할일 클릭 → 몽글 팝업(기존 `ItemDetailPopup` 재사용 검토)에서 제목·우선순위·마감·담당자·상태 수정 + 삭제.
- **보기:** 지금의 "할 일 / 완료" 2열 유지 + (선택) 담당자별 필터 칩("전체 · 쏠 · 민석 · 미배정 · 🤖 AI").
- **뷰 전환(선택, 후속):** 리스트 ↔ 칸반(todo/in_progress/done). 개인 셸 `TasksPage`에 이미 칸반 있음 → 컴포넌트 재활용.

**데이터모델:** 신규 컬럼 없음(`tasks.assignee_id` 존재). Mock 3곳 이미 반영됨(빌드 A). → **마이그레이션 불필요.**

**AI 연동:** 직원이 만든 할일도 담당자 지정 가능 → "AI가 초안 → 사람이 담당 배정" 흐름.

**완료기준:** 오피스 할일에서 직접 추가·수정·삭제 가능, 시목에서 쏠/민석에게 배정하면 담당 배지가 뜨고 담당자별로 거른다.

## A2. 오피스 일정 — 동작 확인 + UX 보완

**현재:** 이미 워크스페이스 스코프로 "+ 새 일정" 됨. 사용자가 "안 된다"고 느낀 건 (a) 할일과 혼동, 또는 (b) 버튼 위치를 못 찾음일 가능성.

**설계(가벼움):** "+ 새 일정" 버튼을 헤더 우상단 고정으로 눈에 띄게 + 빈 상태에 "＋ 첫 일정 추가" CTA. 일정에도 **담당자(선택)** 필드 추가 검토(회의/촬영을 누가 담당하는지). → `schedules.assignee_id` 추가 시 마이그레이션 + Mock 3곳.

**완료기준:** 오피스 일정에서 새 일정이 바로 눈에 띄게 추가된다.

## A3. 회사 로드맵 / 백로그 — "앞으로 할 것" 공간

**목적:** 단발 할일 말고 *중기 방향*("8월 오픈 → 첫 구매 → 후기 → 매출 1천만"처럼)을 적어두는 공간. 레퍼런스의 "하루 단위 마케팅 전쟁 계획"도 여기 산다.

**현재:** `projects`/`goals`/`kpis` 테이블은 있고 개인 셸에서만 노출. 이미 `workspace_id` 스코프 가능성 높음(확인 필요).

**설계:**
- 오피스 NAV에 **`프로젝트`(또는 `로드맵`)** 메뉴 추가. `projects`를 워크스페이스 스코프로 리스트 → 목표(`goals`)·KPI(`kpis`) 하위 표시(개인 셸 `ProjectDetailPage` 재활용).
- 각 목표에 할일(`tasks.goal_id`)을 연결해 "이 목표를 위해 할 것" 백로그로 굴림.
- **캠페인 타임라인(선택):** 목표에 시작/종료일 → 간단한 주간 타임라인 뷰(오픈 D-day 카운트). `GoalTimeline` 컴포넌트 존재 → 재활용.

**데이터모델:** `projects`/`goals`/`kpis`에 `workspace_id` 없으면 추가(마이그레이션 + 백필 + Mock 3곳). 있으면 UI만.

**완료기준:** 시목 오피스에서 "8월 오픈 캠페인" 프로젝트 아래 목표·KPI·할일을 묶어 본다.

## A4. 협업 마감 (시목, 둘이)

1차 Phase 6(공유·협업)에서 남은 조각을 여기서 닫는다.
- 할일/일정 **담당자 배정 + 담당자별 필터**(A1/A2).
- (선택) 할일 코멘트/체크리스트 — 후순위.
- 활동 로그(`ActivityView`)에 "쏠이 X 할일 추가 / 민석이 담당 맡음" 반영(이미 `workspace_activities` 존재 → 이벤트만 추가).
- ⚠️ 민석 실제 초대는 **컨텍스트 스코핑(빌드 B) 검증 후** — 1차 문서 경고 승계.

# Part B. 콘텐츠 마케팅 특화 (개편레퍼런스 반영)

> 시목은 소싱/상세페이지형 커머스보다 **콘텐츠(릴스·쇼츠)로 고객을 모으는** 구조.
> 레퍼런스가 직접 못박은 우선순위: **성과 누적(⑤) > 트렌드 레이더(③) > 링크 분석(④)**. ("인터넷 인기글 찾기보다 시목 전용 데이터가 훨씬 중요" — 레퍼런스 238줄)

## B1. 콘텐츠 성과 DB + 시목 공식 (★콘텐츠 축 1순위)

**목적:** 올린 콘텐츠 지표를 **수기로 축적** → 시목 전용 패턴("집 콘텐츠가 부부 콘텐츠보다 팔로우 전환↑", "'10년 쓴다'가 '티크'보다 조회↑", "17~24초가 35초보다 완주율↑")을 AI가 도출.

**현재:** 유튜브 기능(`youtube.service.ts`, `WeeklyTrendChart`)은 **내 채널 API 데이터 한정 + 유튜브만**. 플랫폼 무관 수기 지표 입력·누적·패턴분석 없음.

**데이터모델 — 신규 테이블 `content_posts`:**
| 컬럼 | 타입 | 비고 |
|---|---|---|
| id / workspace_id / user_id | uuid | 워크스페이스 스코프, RLS |
| platform | text | reels/shorts/instagram/youtube/tiktok |
| title | text | 릴스 제목 |
| content_type | text | **욕망 / 정보 / 세계관 / 비하인드** (B2 비중과 연동) |
| posted_date | date | |
| views / likes / saves / shares / comments | int | 저장·공유가 시목 핵심지표 |
| follower_delta | int | 게시 후 팔로워 증감 |
| duration_sec | int | 완주율 상관용 |
| note | text | 자유메모 |

- **Mock 3곳 동기화**(`types.ts` `ContentPost`(camelCase) / `content.service.ts` Row(snake) / `mockSupabase.ts` 매핑) + 마이그레이션 `NNN_content_posts.sql` + `DATA_SCHEMA.md`.

**UI:** 오피스 `콘텐츠` 메뉴에 탭 추가("성과"). 레퍼런스식 빠른 입력(제목·조회·좋아요·저장·공유·댓글·팔로워+N) → 리스트 + 간단 추이(SVG, `WeeklyTrendChart` 패턴 재활용, 외부 차트 라이브러리 없음).

**AI 연동:** `analyst` 직원에 신규 `outputKind: 'content_formula'`. 일과 "콘텐츠 공식 리포트" → `content_posts` 누적 읽어 유형별 전환율·표현별 조회·길이별 완주율을 해석 + 다음 촬영 제안. (누적 30건↑부터 유의미 — 리포트에 표본수 명시, 무리한 단정 금지.)

**완료기준:** 릴스 성과를 수기로 쌓으면 analyst가 "시목은 X가 Y보다 잘 된다(n=OO)"를 뽑는다.

## B2. 콘텐츠 비중 관리 (욕망40/정보25/세계관20/비하인드15)

**목적:** 콘텐츠 유형별 목표 비중 vs 실제 비중을 보여줘 균형 유지.

**설계:** `content_posts.content_type`(B1) 집계로 최근 N개 실제 비중 도넛/바 + 목표선. 워크스페이스 설정에 목표비중 저장(`brand_contexts`에 `content_mix` JSON 또는 별도 소규모 설정). SNS 직원 캘린더 생성 시 목표비중을 프롬프트에 주입("이번 주는 세계관이 부족 → 세계관 2개 배치").

**완료기준:** 성과 탭에서 "이번 달 욕망 55% / 정보 10%… 정보·세계관 부족"이 한눈에.

## B3. 트렌드 레이더 직원 (③)

**목적:** 매일 "레퍼런스 5~10개 → 8축 분해(첫1초·첫문장·구도·길이·감정·반전·정보성·댓글이유) → 시목 공식 추출 → 시목 버전 변환 → **오늘 촬영할 3개**".

**설계:** 신규 직원 타입 `trend_radar`(`staffCatalog.ts`에 추가), 모델 `research`(Perplexity→Claude), 신규 `outputKind: 'trend_radar'`. 일과 "오늘의 레퍼런스 스캔"(daily). 레이더 카테고리 = 레퍼런스 181줄(집꾸미기/주방/살림/리빙/홈카페/원목/편집숍/중년여성 라이프…).

**⚠️ 데이터소스 한계(중요):** Perplexity는 *화제 콘텐츠를 텍스트로 검색*은 하지만 **영상 자체(첫 1초·구도)는 못 본다.** 따라서 트렌드 레이더의 "왜 떴나"는 텍스트 기반 추정이고, **정밀 분석은 B4(사용자가 링크/영상 던지기)와 세트**로 가야 실효. → B3·B4를 한 Phase로 묶는다.

**완료기준:** 아침 브리핑에 "오늘의 레퍼런스 + 시목 버전 촬영각본 3개"가 뜬다.

## B4. 링크/영상 7단계 분석 (④)

**목적:** 쏠닝이 릴스 링크(또는 화면녹화·스샷)를 던지면 7파트로 분해: ①왜 떴나 ②훅 구조 ③시청 욕망 ④시목 접점 ⑤따라하면 안 될 부분 ⑥시목 버전 3개 ⑦실제 대본.

**설계:** `trend_radar`(또는 `sns`) 직원의 **"직접 시키기"** 모드. 입력: 링크 + **영상 스틸/스샷 이미지 업로드**. 이미지는 Claude vision(opus/sonnet 비전)로 프레임 분석 → 레퍼런스 211줄 "화면녹화 보내면 프레임 단위" 요구 충족. 신규 `outputKind: 'link_teardown'`(7파트 구조 뷰). 결과의 "시목 버전 3개"는 B1 촬영 아이디어/할일로 저장 가능.

**완료기준:** 링크+스샷 던지면 7파트 리포트가 나오고, 시목 버전 3개를 할일로 저장한다.

## B5. 브랜드 전략실 강화 (①)

**목적:** 모든 직원 판단의 헌법 강화 — 핵심문장·1년목표·절대피할방향·4대 판단기준.

**현재:** `brand_contexts`(identity/tone/usp/story/target…)를 전 직원 프롬프트 최상단 주입(`brandContexts.service.ts`). 그릇은 있으나 아래 필드가 없음.

**데이터모델 — `brand_contexts` 컬럼 추가:** `core_sentence`("좋은 것은 시간을 담는다") · `one_year_goal` · `anti_direction`(절대 피할 방향: "수입잡화점처럼 보이기") · `judge_criteria`(4대 기준: 시목다움/기억할 이유/팔리나/확장되나). → 마이그레이션(nullable) + `DATA_SCHEMA.md` + Mock 3곳(`BrandContext` 타입/서비스 Row/`mockSupabase`).

**설계:** `BrandView`(전략실 편집 화면)에 필드 추가. `buildSystemPrompt`/직원 SOP 조립부에 주입. (선택) 직원 산출물 하단에 "4대 기준 셀프체크" 한 줄.

**완료기준:** 전략실에 4대 기준을 넣으면 모든 직원 산출물이 그 기준을 반영/자기점검한다.

# Part D. 열린 결정 (착수 전 확인)

1. **Phase 9 할일 뷰 형태:** 지금 2열(할 일/완료) 유지 + 추가폼 vs 개인셸 칸반 이식 — **추천: 2열 유지 + 추가폼(최소변경)**, 칸반은 후속.
2. **담당자 모델:** `assignee_id`(단일) 유지로 충분? 공동담당은 당장 불필요로 보임.
3. **`projects`/`goals`/`kpis`에 `workspace_id` 존재 여부** — Phase 10 착수 시 스키마 실측 필요(없으면 마이그레이션+백필).
4. **콘텐츠 유형 4분류 고정 vs 커스텀** — 레퍼런스 40/25/20/15 고정 시작, 커스텀은 후속.
5. **트렌드 레이더 데이터소스** — Perplexity 텍스트 검색만으로 시작(영상 정밀분석은 B4 사용자 업로드에 의존)에 동의하는지.
6. **오픈 캠페인 플랜(오늘 8/1 오픈)** — 이건 코드가 아니라 *콘텐츠 산출물*. 기능화(A3 타임라인)와 별개로, 지금 당장은 회의실/전략실 직원에게 뽑게 하는 게 빠름.

> 위 결정들은 각 Phase 착수 직전 확정. **Phase 9(오피스 할일 운영화)부터 착수 권장.**
